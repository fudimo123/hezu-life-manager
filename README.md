# 🏠 合租生活管家（CoLiving Mate）

> 美团 AI Coding 考试作品 · 面向合租青年的生活协作工具
> **在线地址：https://fudimo123.github.io/hezu-life-manager/**

## 一、产品定位

**一句话：把「口头约定」变成「自动提醒」，把「不好意思开口」变成「系统帮你说」。**

年轻人合租生活中的高频矛盾，几乎都源于「账没算清」和「约定没人执行」。本产品用一个应用整合 **费用 AA 分摊、清洁值日排班、公共物品管理、室友公约管理** 四大场景，通过「记录 — 计算 — 提醒 — 执行」闭环，让合租关系中的每一件事都有据可依、自动运转。

## 二、用户痛点与机会点

| # | 痛点 | 用户原声（调研） | 产品方案 |
|---|------|------------------|----------|
| 1 | 钱算不清 | 「新人只住了 20 天，凭什么摊一整个月水电？」 | 三种分摊算法（均摊 / 按入住天数 / 自定义）+ 自动结算中心 |
| 2 | 活没人干 | 「值日表贴了一个月，动的永远是同一个人。」 | 自动轮值排班 + 到点提醒 + 打卡积分榜 |
| 3 | 东西没人买 | 「垃圾袋用完了才发现，最后都是同一个人默默下单。」 | 物品登记 + 消耗记录 + 低库存预警 + 补货自动入账 |
| 4 | 约定没约束 | 「说好 11 点安静，转头就忘；当面不好意思说。」 | 公约电子化 + 在线投票生效 + 全员签署 + 违约留痕 |

**数据打通设计**：成员「入住/退租日期」是底层关键数据 —— 自动驱动费用按天分摊、值日轮值名单更新，一个数据变更，全屋规则同步更新。

## 四、核心流程

1. **费用结算闭环**：垫付人记一笔 → 选分摊方式 → 系统自动算账 → 结算中心生成「谁转给谁」→ 还款确认结清。
2. **值日执行闭环**：设定任务与频率 → 系统排班 → 到点提醒 → 完成打卡 → 积分入榜。
3. **物品补货闭环**：登记公共物品 → 日常消耗记录 → 低于阈值预警 → 一键补货 → 补货费用入账单。
4. **公约生成闭环**：发起草案 → 室友投票 → 达到比例生效 → 全员签署 → 违约记录留痕。

## 五、核心算法说明

- **AA 均摊**：按账单日活跃成员人数均分，尾差自动摊入最后一人。
- **按入住天数**：按账单周期内每位成员的实际入住天数折算比例（`share = amount × 入住天数 / 总人天`），新室友、退租自动按天计算。
- **自定义**：手动输入每人金额，校验分摊合计与总额一致。
- **自动结算**：`净额 = 垫付 − 应摊`，将债权人与债务人按金额排序匹配，生成**最少笔数**的转账方案（贪心配对）；附一键复制催收话术。
- **对账确认**：室友逐笔确认账单无误，全员确认后标记「已对账」归档。
- **值日轮值**：`值日人 = 轮值名单[(应值日次数 − 1) mod 名单长度]`，按自然日推进；请假自动顺延下一位，天然支持轮休与新人插入。
- **退租清算**：`应退金额 = 押金份额 − 未结清欠款`，与退租日期联动自动计算。

## 六、技术实现

- 纯前端：HTML + CSS + 原生 JavaScript，**零框架、零后端、零构建**。
- 数据持久化：浏览器 `localStorage`（100% 本地，隐私安全），支持 JSON 导出/导入备份。
- 部署：GitHub Pages 静态托管，长期免费、域名稳定、公开访问。
- 适配：移动端优先（含 iPhone 安全区），桌面端居中适配。

## 八、部署与迭代规范（域名永不更换）

> ⚠️ **项目铁律：作品唯一入口为 `https://fudimo123.github.io/hezu-life-manager/`，所有迭代只更新此站点，禁止更换域名。**

- **域名机制**：GitHub Pages 域名与仓库名（`fudimo123/hezu-life-manager`）永久绑定，仓库不可重命名、不可删除，域名即永久稳定。
- **迭代方式**：更新本仓库代码后重新部署即可，链接不变。两种方式：
  1. 在 GitHub 网页端直接编辑仓库文件，保存后 Pages 自动重新构建（约 1 分钟生效）；
  2. 本地改完代码，用固化脚本部署：
     ```powershell
     $env:GH_TOKEN = (gh auth token)
     node deploy/deploy-pages.js
     ```
     （本机直连 github.com:443 的 git push 被网络阻断，故脚本走 GitHub API 上传；脚本内 OWNER/REPO 为固定常量，自动跳过未变更文件，构建完成后打印不变的站点地址。）
